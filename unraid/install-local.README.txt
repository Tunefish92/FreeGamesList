FreeGamesList on Unraid (private install, no registry)
======================================================

Contents
  freegameslist-image.tar.gz   the Docker image (website + daily worker), built from commit COMMIT
  install.sh                   installs, updates and rolls back

Install or update (Unraid terminal: the >_ icon top right in the web UI)
  bash /mnt/user/filesharing/unraid-share/freegameslist/install.sh

  The script notices by itself whether it's the first install or an update. Explicitly:
    bash /mnt/user/filesharing/unraid-share/freegameslist/install.sh update
    bash /mnt/user/filesharing/unraid-share/freegameslist/install.sh rollback

  - Site on port 8092. Another port for the first install:
      PORT=8095 bash /mnt/user/filesharing/unraid-share/freegameslist/install.sh
    Updates keep the port the site already runs on.
  - Data (the database with all game lists): /mnt/user/appdata/freegameslist
  - Two containers show up in the Docker tab with icon, and start again after a reboot
    (restart policy "unless-stopped"):
      freegameslist          the website (WebUI entry); only reads the database
      freegameslist-worker   fetches all stores every day at 15:00 (server time zone) and
                             retries failed stores 3 times, 10 minutes apart

What an update does
  1. Stops both containers, so the database is closed cleanly.
  2. Backs up the database to /mnt/user/appdata/freegameslist-backups (the last 5 are kept).
  3. Keeps the running version as "previous", loads the new image, recreates the containers.
  4. Waits until the site answers, then checks that the database still holds all game lists
     (one per region and language) and that the site serves them.
  If the new version doesn't start or the lists are gone, it goes back to the previous version
  and the backup by itself. "install.sh rollback" does the same by hand.

  Everything in the database can be fetched again from the stores, so there is no nightly
  backup: losing it only means waiting for the next update.

First start
  1. Open http://<unraid-ip>:8092 from your home network. Right after the install the list is
     empty: the worker fetches all stores at once (a few minutes; Docker tab >
     freegameslist-worker > Logs). After that it updates every day at 15:00, and right after a
     start when the last good update is older than a day.
  2. Cloudflare Tunnel: public hostname freegames.tunefishservers.net -> http://<unraid-ip>:8092

Settings (put them in front of the command, every time you run it)
  CRON_SCHEDULE="0 6,15 * * *"   when the stores are fetched (cron; default: 0 15 * * *)
  UPDATE_REGIONS=DE,AT,CH        only these regions (default: all 15)
  RETRY_ATTEMPTS=3 RETRY_DELAY_MIN=10   retries for a store that failed
  Example: CRON_SCHEDULE="0 6,15 * * *" bash /mnt/user/filesharing/unraid-share/freegameslist/install.sh update

Start over (deletes the game lists; the worker fetches them again)
  docker rm -f freegameslist freegameslist-worker
  rm -rf /mnt/user/appdata/freegameslist
  bash /mnt/user/filesharing/unraid-share/freegameslist/install.sh install

Notes
  - The Docker tab's "check for updates" shows "not available" for these two containers: the
    image only exists on this server. That's expected.
  - Don't use "Edit" on them in the Docker tab (there's no template); change settings as shown
    above and run install.sh again.
  - Is the data fresh? http://<unraid-ip>:8092/api/health answers 200 with the time of the
    last good update, and 503 when it is older than 26 hours.
